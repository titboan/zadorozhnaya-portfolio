# Zadorozhnaya Portfolio — навигация по проекту

Карта проекта. Читай в начале каждой сессии.
Сайт-портфолио графического дизайнера Zadorozhnaya. Учебный проект: дизайн из Figma → готовый сайт.

---

## Порядок чтения в начале сессии

1. `CLAUDE.md` (этот файл) — правила, структура, навигация
2. `ai-clone/feedback/` — если задача пересекается с прошлыми граблями (Figma, CSS-анимации, Vite, и т.д.)
3. `plans/` — если есть файл со строкой `Статус: в работе`, показать и спросить, продолжать ли
4. Зона задачи — нужный `.claude/skills/*/SKILL.md` (`figma-workflow` для вёрстки секций, `deploy-vercel` перед пушем)

---

## Стек

- **React + Vite** — компоненты, dev-сервер
- **CSS** (без Tailwind) — обычный CSS с переменными, понятно как Figma → CSS
- **Без бэкенда** — статический сайт
- **`vite-plugin-image-optimizer`** (`vite.config.js`) — сжимает JPEG/PNG/SVG в `public/images` при каждом `npm run build` (Sharp + SVGO), не трогает исходники в репозитории. Новые картинки в `public/images` можно класть как есть — сожмутся сами при сборке

## Принципы (нарушать только с явным обоснованием)

1. Перед новой секцией — читать дизайн из Figma (`get_design_context`), не угадывать значения. Используй `.claude/skills/figma-workflow/`
2. Один компонент = один `.jsx` файл + одноимённый `.css` файл
3. Все цвета и шрифты через CSS-переменные в `App.css`, не хардкодить
4. После каждой секции — проверить в браузере (`/run`, `npm run dev`), для готовой фичи — `/verify` вместо проверки на глаз
5. Перед работой в знакомой по прошлым сессиям области — свериться с `ai-clone/feedback/` (там технические грабли: Figma blend mode, Vite `public/`-пути, IntersectionObserver + overflow root и т.д.)
6. Структурные изменения (новый компонент/страница, новый механизм деплоя, новая зависимость влияющая на сборку) — обнови этот CLAUDE.md в том же коммите

## Большая фича = план в `plans/`

Создай план если: затронуто 2+ файла, добавляется новая страница/раздел, или ты сам не уверен в объёме. Сомневаешься — создай план.

Формат: имя `YYYY-MM-DD-название-задачи.md`, строка `Статус: в работе / завершён` в начале, фазы/части с чек-боксами `[ ]`/`[x]`.

Не успел закончить фазу за сессию — закоммить то, что прошло проверку, отметь фазу `[~] в процессе` в файле плана, не оставляй незакоммиченный код.

## Правила репо

1. `git add` поимённо — никогда `git add .` или `git add -A` (оба в deny в `.claude/settings.json`)
2. **Ветка и PR**: если сессия/харнесс сама указала рабочую ветку (Claude Code на вебе/GitHub) — работай в ней; PR открывай только если попросили явно. Если работаешь локально в CLI без указанной ветки — пушь прямо в `master` (Vercel деплоит только с `master`)
3. Перед `git push` — проверить `git log origin/<branch>..<branch> --oneline`, что реально уходит
4. Если нужная папка не существует (`plans/`, `retrospectives/` и др.) — создай и продолжай
5. Коммиты — Conventional Commits: `feat(scope): …`, `fix(scope): …`, `docs(scope): …`, описание на русском

## Известные ограничения (актуально на 2026-07-20)

- Figma MCP на бесплатном тарифе — ~6 вызовов чтения в месяц, экономь их (см. `retrospectives/2026-06-18_figma-export-rate-limit.md`)
- Автосжатие картинок настроено (`vite-plugin-image-optimizer`, см. ниже), но конвертации в WebP/AVIF и линтера (`eslint-plugin-jsx-a11y`) пока нет — отслеживается в `plans/2026-07-20-workflow-modernization.md`, не дублировать эту работу без сверки с планом
- Тестов нет и не планируются для этого проекта — проверка через `/run` + `/verify` и ручной просмотр в браузере
- В этой облачной сессии `localhost`/loopback недоступен из Bash/PowerShell даже когда сервер реально поднят в фоне (проверено на `vite preview`) — живую проверку в браузере (`/run`) здесь не прогнать, только целостность собранных файлов вручную (валидность картинок, наличие путей). Для полноценной проверки в браузере — локальная сессия на компьютере Бори

## Деплой

Сайт живёт на Vercel: https://zadorozhnaya-portfolio.vercel.app  
Каждый `git push` в ветку `master` → автоматический деплой.  
GitHub Actions (`build-check.yml`) гоняет `npm run build` на каждый push/PR — ловит сломанную сборку до Vercel. Подробности — `.claude/skills/deploy-vercel/`.

## Команды

```bash
npm run dev      # запустить dev-сервер → localhost:5173
npm run build    # собрать для деплоя
npm run preview  # посмотреть сборку локально
npm run lint     # ESLint + jsx-a11y (eslint.config.js) по src/
```

1. Найди ошибки → докажи примером → исправь
2. Что упустили: мобильная вёрстка, пустые/длинные состояния текста, hover/focus
3. Реальная проблема этого проекта? Сверь с `ROADMAP.md` / `plans/`, не делай лишнего
4. Свежий взгляд — перечитай diff как будто видишь впервые
5. Проверь: не попал ли в коммит файл >2 МБ или случайный `.env`/токен
6. Фича готова к пушу когда: цикл пройден, план (если был) обновлён `[x]`, проверено в браузере (`/run` / `/verify`)
