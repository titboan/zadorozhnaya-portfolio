## Когда использовать

При реализации любой новой секции/кейса или при вопросах про цвета/отступы/шрифты — вместо `figma-workflow`, когда работаешь локально на компьютере Бори (VS Code, MCP-сервер `Lunacy` подключён, `claude mcp list` показывает Connected).

В облачной сессии (веб/GitHub) эти инструменты недоступны — там используй `figma-workflow` как раньше.

## Отличие от Figma MCP

Figma MCP адресуется по `fileKey` + `nodeId` без участия человека. У Lunacy MCP нет прямой адресации по nodeId — сначала **Боря выделяет** нужный фрейм/слой в открытом окне Lunacy, потом Клод читает выделенное.

## Порядок работы

1. **Попросить Борю выделить** нужный фрейм/слой в Lunacy (например, кейс целиком или конкретную секцию)
2. **`get_format_documentation`** — один раз в сессии, если ещё не читал структуру FREE-формата в этой сессии
3. **`get_selected`** — получить выделенное в JSON (.free формат): цвета (`fill`/`fills`), размеры (`size`), отступы (`autoLayout.padding`/`spacing`), текстовые стили
   - Ответ может быть большим (сотни строк) — если превышает лимит вывода, результат сохраняется в файл, читать чанками через offset/limit
4. **`get_viewport_info`** / **`get_screenshot_viewport`** — если нужно посмотреть, что сейчас видно на экране, без выделения (скриншот может отваливаться таймаутом на больших фреймах — не считать это поломкой связи, повторить или запросить `get_selected` вместо скриншота)
5. **Извлечь:** цвета (HEX), шрифты, отступы — так же, как из Figma
6. **Перенести в CSS-переменные** (`App.css`) если новый токен
7. **Скачать ассеты:** `export` с `layerIds` (ID слоя из `get_selected`), `format: JPG/PNG/SVG/...`, `scale` — картинку **не сохраняет на диск**, только показывает превью в диалоге (проверено 2026-07-21 — обысканы temp-папки Lunacy/Icons8, кэш MCP-логов, вся сессионная директория Claude Code, нигде не появляется файл с байтами). Годится только для визуальной проверки, не для получения файла. Реальный файл на диск — только через `figma-workflow`/`download_assets`, либо Боря экспортирует вручную (File → Export) в самой Lunacy

## Если нужно что-то ИЗМЕНИТЬ в файле (переименовать/удалить/создать)

⚠️ **`update_layers`/`create_layers`/`delete_layers`/`duplicate_layers` по произвольным ID не гарантированно пишут в реальный документ** — проверено 2026-07-21: вызов вернул успех, `get_layers_by_ids` сразу после подтвердил новые данные, но после того как Боря просто сохранил файл (без перезагрузки) — значение откатилось на старое, а запись из `get_undo_stack` пропала. Подробности и разбор причины — `ai-clone/feedback/lunacy-mcp-write-by-id-unreliable.md`.

Единственный официально протестированный (release notes icons8, v11.6 «LLM can edit Selection over MCP») и на практике надёжный способ писать — через ТЕКУЩЕЕ ВЫДЕЛЕНИЕ:
1. Попросить Борю выделить нужное в живом Lunacy
2. `get_selected` — получить точный JSON с реальными ID
3. Собрать изменённую копию (переименование/группировка/трансформация), **сохранив те же ID**
4. `set_selected` с этой копией — это заменяет выделение и реально пишет в документ
5. Попросить Борю посмотреть глазами на результат в панели — не доверять повторному API-чтению сразу после записи как единственному подтверждению (может быть тем же кэшем/эхо)

Если правка большая (десятки объектов) и просить каждый раз ручного выделения дорого — явно предупредить пользователя, что группового программного rename по ID не будет и предложить: либо ручное выделение по частям, либо Боря делает изменения сам в UI.

## Известные грабли

- Первый способ открыть файл в Lunacy (`Ctrl/Cmd+V` — Open URL From Clipboard) может не сработать молча — использовать `.fig`: в Figma `File → Save local copy`, в Lunacy `File → Open...`
- Несколько наложенных blur-слоёв (frosted glass) при импорте `.fig` схлопываются в один — сверяться с `ai-clone/feedback/figma-passthrough-blend-mode.md`
- После первого подключения MCP-сервера в `claude mcp add` — инструменты `mcp__Lunacy__*` появляются только после **рестарта** Claude Code, не в уже запущенной сессии
- `export`/`update_layers`/`create_layers`/`delete_layers`/`duplicate_layers` — не доверять успешному ответу как доказательству результата (см. выше и `ai-clone/feedback/lunacy-mcp-write-by-id-unreliable.md`). Только `get_selected`/`get_layers_by_ids`/`get_layers_in_area` (чтение) и `set_selected` (запись через выделение) проверены как реально работающие

## Резервный вариант

Если контента в текущей Lunacy-копии не хватает (кейс/ассет ещё не перенесён из Figma) — использовать `figma-workflow` для конкретно этого пробела, не пересоздавать весь файл заново.

## Проверено на реальной задаче

2026-07-20: `get_selected` на фрейме «солнечный берег» вернул точную структуру (size `[1915, 25361]`, совпадает с данными из Figma), `export` с `scale: 0.3` в JPG дал корректное превью. Подтверждает, что Lunacy MCP пригоден для реальной работы, не только для чтения метаданных.
