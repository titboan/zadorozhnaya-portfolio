# Рефлексия: аудит стека, репозитория и правил (CLAUDE.md)

Дата: 2026-07-20

---

## 1. Какая задача была

Просмотреть весь стек и репозиторий, проверить, что нужно добавить в правила/документацию, соблюдая современные требования к файлу `CLAUDE.md` (и вообще к тому, как Claude Code читает конфигурацию проекта).

---

## 2. Как решали

Прочитали весь репозиторий: `CLAUDE.md`, `ROADMAP.md`, `plans/`, `retrospectives/`, `ai-clone/feedback/`, `.claude/skills/`, конфиги (`package.json`, `vite.config.js`, `vercel.json`, `.gitignore`, `index.html`), структуру `src/`. Сверили список реально подключённых скиллов (системный список доступных skills) с тем, что заявлено в `CLAUDE.md`.

---

## 3. Решили — да, полностью

Главная находка: `.claude/skills/figma-workflow.md` лежал плоским файлом, а не в формате `.claude/skills/<name>/SKILL.md` — из-за этого Claude Code **не видел его как навык вообще** (в списке доступных skills проекта его не было). `deploy-vercel`, упомянутый в `CLAUDE.md`, не существовал физически ни в каком виде.

Исправлено:
- `.claude/skills/figma-workflow/SKILL.md` — правильный формат, навык теперь виден и вызываем
- `.claude/skills/deploy-vercel/SKILL.md` — создан с нуля (чек-лист перед/после пуша в master, привязан к прецеденту с незакоммиченным `lenis`)
- `.github/workflows/build-check.yml` — CI-проверка `npm run build` на каждый push/PR в master, ловит сломанную сборку до Vercel (Vercel сам по себе билд не гоняет как отдельную проверяемую стадию до деплоя)
- `README.md` — раньше отсутствовал; `CLAUDE.md` — файл для AI-агента, а не для человека, зашедшего на GitHub
- `CLAUDE.md` — добавлены принципы, которых не хватало: сверяться с `ai-clone/feedback/` перед похожей работой (файлы были, но ничего не указывало **когда** их читать), писать ретроспективу после крупного блока задач, коммитить в Conventional Commits (уже соблюдалось по факту во всех коммитах, но нигде не зафиксировано), актуальный список известных ограничений (лимит Figma, нет линтера/тестов — со ссылкой на существующий план, чтобы не задваивать работу)

---

## 4. Что можно было лучше

- Формат `.claude/skills/figma-workflow.md` был неправильным с самого начала (вероятно, с первой сессии) — стоило проверять реальную видимость навыка (список доступных skills), а не полагаться на то, что файл существует и назван похоже на правильный.
- `ai-clone/feedback/` — хорошая идея (грабли зафиксированы подробно, с `Why`/`How to apply`), но без явного правила «когда это читать» в `CLAUDE.md` файлы фактически лежали мёртвым грузом.

---

## 5. Что узнал нового о проекте или пользователе

- Claude Code скиллы обнаруживаются только по пути `.claude/skills/<name>/SKILL.md` — плоский `.md`-файл в `.claude/skills/` не регистрируется как вызываемый навык, даже если по смыслу это готовый SKILL.
- В репозитории уже есть параллельный план модернизации (`plans/2026-07-20-workflow-modernization.md`) с похожими по духу пунктами (a11y-линтер, оптимизация картинок, проверка деплоя через Vercel MCP) — важно не задваивать эту работу, а дополнять её (CI — это отдельный, более лёгкий уровень проверки, чем Vercel MCP; линтер там уже запланирован).
