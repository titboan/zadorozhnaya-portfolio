# ESLint 9 flat config молча пропускает .jsx без явного `files`

В ESLint 9 (flat config, `eslint.config.js`) правило по умолчанию для конфиг-объекта без ключа `files` — линтить только `**/*.js`. Если добавить `eslint-plugin-react`/`jsx-a11y` без `files: ['**/*.{js,jsx}']` в каждом блоке, `eslint .` отработает с кодом 0 и без единого сообщения — выглядит как «код чистый», а по факту `.jsx`-файлы вообще не попали в проверку.

Как поймали: `npm run lint` дал 0 проблем сразу после установки плагинов — подозрительно чисто для реального кода. Проверка через `eslint --format json` показала, что линтились только 2 файла (конфиги), а не 16 файлов из `src/`. После добавления `files: ['**/*.{js,jsx}']` в каждый блок конфига нашлись реальные 8 файлов с сообщениями (потом обнулились после других правок — но ключевой урок про `files` не в конкретном числе, а в самом факте молчания).

**Как применять:** после любой настройки/правки ESLint flat config — не доверять «0 ошибок» на глаз. Прогнать `eslint . --format json` и явно посчитать количество линтованных файлов (`results.length`) и сколько из них реально относятся к исходникам, а не только конфигам. Ещё надёжнее — контрольный тест: временно вставить заведомо кривой код (например `<img>` без `alt`) во временный файл в `src/`, убедиться что линтер его ловит, удалить файл.
